Contributing to NGX-Notitia

Thank you for considering contributing to NGX-Notitia! We welcome contributions from the community.

Ways to Contribute

Report Bugs

Found a bug? Open an issue with detailed reproduction steps.

Suggest Features

Have an idea? Start a discussion or submit a feature request.

Improve Documentation

Fix typos, add examples, or clarify confusing sections.

Submit Code

Fix bugs, add features, or improve performance.

Development Setup

Prerequisites

  • Node.js 18+ and npm 9+
  • Angular CLI 21+
  • Git

Setup Steps

1. Fork and clone the repository:

git clone https://github.com/YOUR_USERNAME/ngx-notitia.git
cd ngx-notitia

2. Install dependencies:

npm install

3. Start the development server:

ng serve

4. Build the library:

npm run build

5. Run tests:

npm test

Coding Guidelines

TypeScript

  • Use TypeScript strict mode
  • Provide explicit return types for all functions
  • Avoid any type - use proper typing
  • Use interfaces for object types

Angular

  • Use standalone components by default
  • Use Angular signals for reactive state where appropriate
  • Follow Angular style guide
  • Add ARIA attributes for accessibility

Testing

  • Write tests for all new features
  • Maintain >90% code coverage
  • Test edge cases and error conditions
  • Use descriptive test names

Accessibility

  • Add proper ARIA labels and roles
  • Support keyboard navigation
  • Ensure screen reader compatibility
  • Maintain color contrast ratios

Commit Convention

We follow Conventional Commits: 

<type>(<scope>): <subject>

<body>

<footer>

Types

  • feat - New feature
  • fix - Bug fix
  • docs - Documentation
  • style - Formatting
  • refactor - Code refactoring
  • test - Tests
  • chore - Maintenance

Examples

  • feat(toast): add colorScheme option
  • fix(service): prevent duplicate reset bug
  • docs(readme): update options table
  • test(container): add directive tests

Pull Request Process

1

Create a Feature Branch

Branch from main with a descriptive name: 

git checkout -b feature/amazing-feature
2

Make Your Changes

Follow coding standards and write tests for new functionality.

3

Run Tests and Linter

Ensure all tests pass and code is properly formatted: 

npm test && npm run lint
4

Commit Your Changes

Use conventional commit messages.

5

Push and Create PR

Push to your fork and open a pull request:

git push origin feature/amazing-feature
6

PR Review

A maintainer will review within 3–5 business days. Address any feedback and your PR will be merged!

PR Requirements Checklist

All tests pass (npm test)
Code is linted (npm run lint)
New features have tests
Documentation is updated
Commit messages follow convention
PR description clearly explains changes
No merge conflicts with main branch

Recognition
